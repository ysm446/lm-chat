# 記憶検索の仕組み

LM Chat の記憶検索は、単純なベクトル検索だけではありません。  
現在の実装では、次の 3 つを組み合わせて最終順位を決めています。

1. 全文検索 `FTS5`
2. ベクトル検索 `sqlite-vec`
3. 新しい記憶ほど有利にする時間減衰（半減期）

---

## 1. 何をクエリにして検索するか

記憶検索のクエリは、基本的に「今回の最後のユーザー入力文」です。

- 通常送信時は `payload.content`
- その文字列を embedding モデルでベクトル化して検索ベクトルを作る
- 同時に、その文字列をそのまま全文検索にも使う

つまり、

- 保存されている記憶: 主に `Q: ...\nA: ...` の Q&A チャンク
- 検索クエリ: 今回のユーザー質問文

という構成になっています。

---

## 2. 全文検索

全文検索には SQLite の `FTS5` を使っています。

流れは次の通りです。

1. クエリ文字列を `"..."` で囲み、フレーズ検索用の形にする
2. `memory_fts` に対して `MATCH` を実行する
3. 同じ `workspace_id` の記憶だけに絞る
4. 上位 `top_k * 4` 件を候補として取る

ヒットした記憶には、順位に応じて次の加点をします。

```text
fts_score = 1 / (rrf_k + rank + 1)
```

- `rrf_k = 60`
- `rank` は 0 始まり

例:

- 1位: `1 / 61`
- 2位: `1 / 62`
- 3位: `1 / 63`

これは「上位ほど高得点だが、極端に差をつけすぎない」ための順位ベースの加点です。

---

## 3. ベクトル検索

ベクトル検索には `sqlite-vec` を使っています。

流れは次の通りです。

1. ユーザー入力文を embedding モデルで 768 次元ベクトルに変換する
2. そのベクトルを `memory_vec` に対して KNN 検索する
3. まず `top_k * 4` 件の近傍候補を取る
4. その後で `workspace_id` に一致する記憶だけに絞る

ベクトル検索でも、距離をそのままスコアに使わず、順位に応じて次の加点をします。

```text
vector_score = 1 / (rrf_k + rank + 1)
```

ここでも `rrf_k = 60` です。

つまり全文検索とベクトル検索は、どちらも「順位ベース」で加点されます。

---

## 4. 全文検索とベクトル検索の統合

各記憶チャンクごとに、全文検索とベクトル検索の加点を足し合わせます。

```text
merged_score = fts_score + vector_score
```

もちろん、

- 全文検索だけでヒットした記憶
- ベクトル検索だけでヒットした記憶
- 両方でヒットした記憶

がありえます。

両方でヒットした記憶は、その分だけ加点が大きくなります。

この方式は、厳密な意味での標準 RRF 実装というより、RRF に近い順位融合です。
ただし狙いは同じで、

- 文字列として一致する記憶
- 意味的に近い記憶

の両方を上位に寄せることです。

---

## 5. 半減期による時間減衰

統合後のスコアには、さらに「新しい記憶ほど有利になる」重みを掛けます。

現在の実装では半減期は 30 日です。

まず経過日数を求めます。

```text
days_elapsed = (now - created_at) / 86400秒
```

次に減衰率を求めます。

```text
decay = 0.5 ^ (days_elapsed / 30)
```

最後に最終スコアを計算します。

```text
final_score = merged_score * decay
```

例:

- 作成から 0 日: `decay = 1.0`
- 作成から 30 日: `decay = 0.5`
- 作成から 60 日: `decay = 0.25`

つまり、古い記憶ほど徐々に順位が下がりやすくなります。

---

## 6. 最終的な採用

最終スコア `final_score` の高い順に並べ替え、上位 `top_k` 件を採用します。

採用された記憶はそのままユーザーには返さず、まず次のような形でプロンプト用コンテキストにまとめられます。

```text
## 過去の会話から検索された関連記憶
以下はこのワークスペース内の過去の会話から自動検索された情報です。
ユーザーの質問に答える際、自然に参照してください。

[記憶 1]
Q: ...
A: ...

[記憶 2]
Q: ...
A: ...
```

この記憶コンテキストが、システムプロンプトの末尾に付加されて llama-server に送られます。

---

## 7. まとめ

現在の記憶検索は、次の考え方でできています。

- クエリは最後のユーザー質問文
- 保存記憶は主に `Q: ...\nA: ...` の Q&A チャンク
- 全文検索とベクトル検索の両方を走らせる
- 両検索の順位を足し合わせる
- さらに 30 日半減期の時間減衰を掛ける
- 最終上位だけをプロンプトに入れる

要するに、

- キーワードが近い
- 意味が近い
- しかも比較的新しい

という記憶が優先される設計です。
