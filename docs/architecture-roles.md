# 登場人物と役割分担

LM Chat は複数のプロセス・レイヤーが協調して動いています。それぞれの役割を整理します。

---

## 登場人物

### React / TypeScript フロントエンド（Electron上で動く）

**何をするか：** 画面の描画とユーザー操作の受け付け

- ユーザーの入力を受け取る
- 「送信した」感をすぐ見せる（オプティミスティック表示）
- バックエンドにHTTPリクエストを投げる
- 返ってきたトークンを画面に流し込む
- Zustand（状態管理）でUIの状態を一元管理する

**フロントエンドはDBを直接触らない。** バックエンドのAPIを通じてのみデータを操作する。

---

### FastAPI バックエンド（Python / uvicorn）

**何をするか：** ビジネスロジックとデータの管理

- **DBへの読み書き**（SQLite）→ メッセージ・セッション・ワークスペースの保存と取得
- **記憶の管理** → 会話をベクトル化して保存・検索
- **llama-serverへのプロキシ** → フロントから受け取ったリクエストをllama-serverに中継する
- **システムプロンプトの組み立て** → 「記憶コンテキスト」を付加してllama-serverに渡すメッセージを構築
- **生成統計の記録** → トークン数・速度・時間をDBに保存

---

### llama-server（llama.cpp の実行プロセス）

**何をするか：** AIモデルの推論（テキスト生成）だけ

- バックエンドから渡された会話履歴を受け取る
- モデル（GGUF形式）を使ってテキストを生成する
- 生成したトークンをSSEで1つずつ返す
- DBもUIも一切知らない。純粋に「入力を受け取って出力を返す」だけ

---

### SQLite DB

**何をするか：** データの永続化

- メッセージ・セッション・ワークスペースを保存
- 記憶（ベクトル＋全文検索インデックス）を保存
- Pythonバックエンドのみが直接アクセスする

---

## 関係図

```
[ユーザー]
    ↕ 操作・表示
[React / TypeScript]  ← 画面担当
    ↕ HTTP / SSE
[FastAPI (Python)]    ← ロジック担当・DB管理者
    ↕ HTTP              ↕ SQL
[llama-server]      [SQLite DB]
 (推論専門)          (データ保管)
```

---

## 役割まとめ

| 役割 | 担当 |
|---|---|
| 画面を描く | React / TypeScript |
| データを管理する | Python (FastAPI) |
| AIで文章を生成する | llama-server |
| データを保管する | SQLite |
